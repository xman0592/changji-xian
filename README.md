# 长季鲜 · 私厨会所预约及客情系统

给一家 3 个包厢（VIP1–VIP3）的「福安菜 × 厦门海鲜」私厨会所使用。
纯前端 PWA + 可选 Supabase 多人同步；手机浏览器打开，可加到桌面。

**线上地址**：https://xman0592.github.io/changji-xian/
**仓库**：https://github.com/xman0592/changji-xian

## 功能

- **聊天转订单**：粘贴客人微信聊天，自动识别日期、时间、人数、餐标、包厢、称呼、电话、忌口、口味、场景、指定菜；缺项提示。
- **六步预定流转**：新预定 → 转店长 → 店长出菜单 → 回老板 → 发客户 → 客户确认。每一步状态、操作人、时间都留痕，首页有「待我配菜 / 待我发客户」待办。
- **四角色权限矩阵**：老板、店长、后厨、服务员各一张入口二维码，菜品编辑 / 上下架 / 改价 / AI 配菜 / 备货单 / 邀请函按角色开关（**菜价只有店长能改**）。
- **提前预定主线**：待审核 → 审核通过并通知 → 已完成；改单自动回到待审核，包厢时间冲突提醒。
- **餐标智能配菜**：填人数 + 餐标（每桌/每位），按预算、时令、可预订天数、老客口味出 3 套菜单；客户指定菜会保留，再用剩余预算补齐。老板、店长都能用；**采用菜单时自动按人数排包厢**。
- **包厢容量匹配**：VIP1/VIP2 坐 10–12 人，VIP3 坐 15–18 人；自动排包厢会避开当天已占用（前后 150 分钟）的房间，人少给大房会提示「偏大」。
- **老客口味记忆**：完成订单自动记录常点菜、口味偏好、常餐标、偏好包厢；保存订单时把当次忌口合并进熟客档案（沉淀为核心资产）。同名客户按**手机尾号 4 位**区分，列表和详情显示「王总（尾8899）」。
- **时令菜品**：店长每日点在售 / 需预订 / 下市；客人可打开只读菜单链接自己看。后厨为只读视图（可看备货单，不能改上下架）。
- **熟客档案**：标签、忌口、口味、常点、到店记录、累计消费。
- **备货清单**：按日期汇总已确认订单的桌数、人数、菜品、忌口，复制微信文字或导出 CSV。仅店长、后厨可看。
- **接待看板**：服务员手机看每桌时间、包厢、忌口、特殊安排、亲友回执，并勾选开台准备（碗碟 / 酒水扎壶 / 矿泉水 / 饮料），**数量按人数自动算好**。
- **邀请函**：订单一键生成**微信邀请函长图**（1080 宽、自动裁高），墨绿烫金请柬风格，含店招广告位、**菜品展示（两列大图）**、**环境展示（一宽两半）**、**专属服务经理（可一键拨号）**、门店地址 + **双地图一键导航**（高德 / 百度）；图片保存后直接转发微信，也可转发带导航的 H5 链接。
- **历史台账**：按客人、电话、菜品、日期检索。
- **数据安全**：本机自动快照 10 份，支持导出/导入 JSON 备份。
- **角色入口二维码**：每个角色一张二维码/链接，店员微信扫码直接进入对应身份，手机记住；不依赖认证公众号，可选 4 位密码。
- **多人同步**：Supabase 免费版，老板/店长/后厨/服务员登录同一账号共享数据。

## 邀请函（1.4.0）

一张邀请函有两种形态，内容一致：

1. **微信长图**（1080 宽 PNG，按内容自动裁高，直接保存转发）——**推荐**，微信里就是一张请柬
2. **H5 链接**（`invite.html?d=...`，手机打开，按钮可点）

风格取高端私房菜路数：墨绿底 + 烫金线条、宋体大字、`谨呈 / 台鉴 / 诚邀赴宴 / 敬备菲酌 · 恭候台光 / 谨订于 / 席设` 的请柬措辞。

版块自上而下：店名 → 谨呈 + 主客台鉴 → 诚邀赴宴 → 谨订时间 / 席设包厢人数 → 当日菜单 → **菜品展示**（两列大图，菜名 + 价格）→ **环境展示**（一宽两半：大厅 / VIP 包厢 / 茶歇卡座）→ **专属服务经理**（姓名 / 职务 / 专线，H5 可一键拨号）→ 店招广告位 → **地址 + 双地图一键导航**（高德 / 百度）→ 电子邀请函二维码 → `长季鲜 · 敬约`。

- **导航**：H5 上给「高德地图 / 百度地图」两个按钮，装哪个点哪个，另可一键复制地址发给司机；图片版印地址，提示用地图搜店名。
- **微信转发**：弹层里第一项就是「生成邀请函图片（微信直接转发）」，保存后长按图片即可转发；第二项「转发链接版」在手机上直接拉起系统分享（微信），不会出现一串代码。链接已改为短字段压缩格式，比原版短一半以上。
- **无回执**：1.4.0 起删除「赴宴回执」表单与回执码；亲友忌口直接微信回复，店长在订单里备注。
- 地址在「设置 → 门店地址」维护，默认 `厦门市湖里区天地建材城综合楼东侧二楼`；订座电话默认 `18950071506`。
- 服务经理在「设置 → 服务经理姓名 / 电话」维护，默认 `陈锦长 / 18950071506`；留空时不显示这一块。
- 照片放在 `photos/` 目录，见 `photos/README.md`：`env-1.jpg`~`env-3.jpg`、`manager.jpg`、`dish-菜名.jpg`。仓库里自带一套深绿占位图，把真实照片按同名覆盖即可，不用改代码。

## 预定流转（1.3.0）

订单一进来是六步链，订单详情顶部有流程条，当前步骤高亮，点一下就能推进：

```
新预定  →  转店长  →  店长出菜单  →  回老板  →  发客户  →  客户确认
 (老板)    (老板)      (店长/AI)      (店长)     (老板)     (老板/店长)
```

1. **老板接单**：聊天转订单，保存后在详情页点「转给店长」，会自动生成一段微信话术（人数、餐标、忌口、特殊安排、日期包厢），复制后发店长。
2. **店长出菜单**：店长首页「待我配菜」里能看到这单，点「AI 配菜」——填人数 + 餐标，系统出 3 套并**自动排包厢**，采用后订单的包厢、菜单、菜价一起更新，同时把忌口写进熟客档案。
3. **回老板**：店长点「发给老板」，复制菜单话术（逐道菜 + 合计 + 人均）。
4. **发客户**：老板点「发给客户」，复制一段询价话术（是否够吃、要不要加/减菜）。
5. **客户确认**：客户回话后点「客户已确认」，订单进入可发邀请函状态。
6. **发邀请函**：老板、店长都能生成海报或 H5 链接，转发给主客，由主客再转给同席客人。

每一步都写进 `order.flow.history`（阶段、时间、操作人），同步到云端时塞在 `audit` 字段里，不改云端表结构。

## 角色入口二维码

- 老板/店长在「更多 → 角色入口二维码」里生成四张：老板、店长、后厨、服务员。
- 每张二维码就是 `index.html?role=boss|manager|kitchen|service` 的链接；微信扫码后自动进入对应身份，手机 localStorage 记住，下次直接进入。
- 二维码里是普通网址，**不需要认证公众号、不需要后端**。它只是角色入口，不是微信实名认证；谁拿到链接都能进对应角色，建议给老板/店长设 4 位密码。
- 二维码根据当前打开地址生成。`localhost` / `file://` 生成的二维码手机扫不到，需要先部署到 GitHub Pages/自己的域名，或用电脑局域网 IP 打开后再生成。
- 真微信识别身份（知道扫码人是谁）才需要认证公众号/微信开放平台 + 后端换取 openid，本版本未接。

## 多人同步（Supabase 免费版）

1. 打开 https://supabase.com 注册并新建一个免费项目（区域选新加坡/东京都可以）。
2. 左侧 **SQL Editor** → New query → 粘贴 `supabase-setup.sql` 全文 → Run。
3. 左侧 **Authentication → Users → Add user**，建一个店员共用账号：
   - 邮箱：如 `staff@changjixian.com`（不需要真实收件）
   - 密码：设一个店里都知道的强密码
   - 勾选 **Auto Confirm User**
4. 左侧 **Project Settings → API**，复制：
   - Project URL（`https://xxxx.supabase.co`）
   - `anon` `public` key
5. 在 App 的「设置 → 多人同步」里填 URL、anon key、店员邮箱和密码 → 登录并同步。
6. 其他手机重复第 5 步，登录同一个账号即可。

> 权限设计：店员账号（authenticated）可读写全部数据；未登录的匿名访客只能**新增**亲友回执、只能读取两个公开视图（菜单和门店信息），读不到订单和客人资料。

> 本地已有示例/正式数据时，第一次登录会提示自动上传到云端（远端表为空时全量推送）。之后每 22 秒拉取一次，改动即时推送。

## 数据与备份

- 本机数据：localStorage `cjx_state_v1`；快照 `cjx_snaps_v1`（最近 10 份）；同步配置 `cjx_sync_v1`；增量同步游标 `cjx_sync_cursor_v1`（换账号/清数据会自动作废）。
- 快照策略：保存订单、审核、改单、导入、改设置这类关键动作必打快照；勾选开台准备、改菜品状态等高频小操作最多每 2 分钟合并成一份，避免每次点击都重写 10 份全量数据。
- 换手机、清理缓存前：设置 → 数据安全 → 导出备份。
- 新手机：导入备份，再登录同步账号。
- 微信里打开和桌面 PWA 的 localStorage 是两套，固定用一种方式打开。

## 同步机制（1.2.3 起）

- 首次登录、以及每 30 轮（约 11 分钟）做一次全量拉取，其余轮次只按 `updated_at`（回执按 `submitted_at`）拉有变动的行，订单越多越省流量。
- 增量拉取会往回多看 5 分钟（手动同步 10 分钟）做重叠，重叠部分合并时幂等丢弃，用来兜住各手机时钟偏差。
- 老项目升级：重跑一次 `supabase-setup.sql` 里的 `create index` 语句（给 `cjx_customers` / `cjx_rooms` / `cjx_rsvps` 补索引），增量查询才不会全表扫。

## 换菜系 / 改菜单

默认菜品来自 `D:\长季鲜\福安特色菜.xls` 的 40 道福安特色菜，另加 3 道基础配菜（时令时蔬、蒜蓉时蔬、时令果盘）保证配菜完整；小吃只有「穆阳花饺」，没有福安炖罐。菜价是参考价，第一次使用请在「时令菜」里按实际采购改。

将来做其他菜系：

1. 设置 → 门店信息 → 改「菜系」和「经营定位」。
2. 准备一个菜品 JSON 数组（字段：`name`、`category`、`price`、`status`、`leadDays`、`tags`、`flavor`、`note`），在设置 → 数据安全 → 导入新菜系。
3. 导入会替换菜品库，不影响历史订单里的菜名和价格。

菜品字段说明：

- `category`：冷菜 / 热菜 / 汤 / 主食 / 甜品
- `status`：`on` 在售、`preorder` 需提前预订、`off` 下市
- `leadDays`：需提前几天（仅 `preorder` 生效）
- `tags`：忌口过滤用，如 `海鲜`、`素`、`猪`、`牛`、`辣`、`蛋`、`坚果`
- `flavor`：口味匹配用，如 `清淡`、`鲜`、`清蒸`、`红糟`、`沙茶`、`滋补`、`浓`、`甜`

- PIN 只防误触，不是账号安全体系。
- 邀请函在本地模式不会自动回写，需要把回执码复制回订单。
- 二维码里的导航链接是高德 `uri.amap.com`，手机上装了高德/百度地图会唤起 App，没装就走网页版；iOS 的微信内置浏览器可能提示"在浏览器中打开"。
- 邀请函海报是 Canvas 现场绘制的（1080×1920），没有服务端渲染；超长菜名会自动折行，但一首诗长度的菜名仍可能被截断。
